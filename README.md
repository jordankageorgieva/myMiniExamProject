# Daily Task Manager

## Overview

**Daily Task Manager** is a Django web application designed to help users organize their daily activities, manage tasks, and track their progress. The application provides a structured way to create, categorize, and manage tasks through a simple and intuitive interface.

The project demonstrates the use of Django models, forms, class-based views, template rendering, data validation, and database relationships.

## Features

- **User Profiles** – Create and manage user profiles with a unique username and email address.
- **Task Management** – Create, view, edit, and manage daily tasks.
- **Task Status Tracking** – Organize tasks by status: `TODO`, `IN_PROGRESS`, and `DONE`.
- **Categories** – Organize tasks into categories such as Education, Hobby, Work, and Personal.
- **Task Descriptions** – Add optional descriptions with additional information.
- **Due Dates** – Set optional deadlines for tasks.
- **Automatic Timestamps** – Record when a task is created.
- **Data Validation** – Validate user input according to the defined model requirements.
- **Static File Management** – Serve CSS, JavaScript, and image files using WhiteNoise.
- **Dependency Management** – Install the required Python packages using `requirements.txt`.

The `static/` directory contains the original static assets. The `staticfiles/` directory is generated by Django's `collectstatic` command and should not be used as the source directory for editing CSS files.

## Data Models

### Profile

Represents a user profile within the application.

- `username` – Required, 2–15 characters; letters, numbers, and underscores only.
- `email` – Required email address.
- `age` – Optional integer greater than or equal to zero.

### Task

Represents an individual task.

- `title` – Required text, maximum 100 characters.
- `description` – Optional text.
- `status` – Task status: `TODO`, `IN_PROGRESS`, or `DONE`.
- `created_at` – Automatically generated creation timestamp.
- `due_date` – Optional deadline.
- `profile` – Required relationship to a profile.
- `category` – Optional relationship to a category.

### Category

Represents a category used to group related tasks, such as Education, Hobby, Work, and Personal.

## Installation and Setup

### Prerequisites

- Python compatible with the project's Django version.
- PostgreSQL.
- Git.

### 1. Clone the repository

```bash
git clone <repository-url>
cd DailyTaskManager
```

Replace `<repository-url>` with the actual GitHub repository URL.

### 2. Create a virtual environment

```bash
python -m venv .venv
```

Activate it on Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

### 3. Install dependencies

```bash
python -m pip install -r requirements.txt
```

The `requirements.txt` file contains the Python packages required by the application, including Django and WhiteNoise.

### 4. Configure the database

Configure the PostgreSQL connection using the project's database settings or environment variables, depending on the implementation.

Do not commit database passwords, secret keys, or other sensitive configuration values to GitHub.

### 5. Configure static files

In `settings.py`, configure the static file settings:

```python
STATIC_URL = "/static/"

STATICFILES_DIRS = [
    BASE_DIR / "static",
]

STATIC_ROOT = BASE_DIR / "staticfiles"
```

Add WhiteNoise immediately after Django's `SecurityMiddleware` in `MIDDLEWARE`:

```python
MIDDLEWARE = [
    "django.middleware.security.SecurityMiddleware",
    "whitenoise.middleware.WhiteNoiseMiddleware",
    # Keep the remaining middleware entries here.
]
```

For production-style static file serving, collect the static assets:

```bash
python manage.py collectstatic
```

WhiteNoise can serve collected static files when configured correctly. For local development, Django's normal development server can serve static files when `DEBUG = True`. When `DEBUG = False`, verify the static file configuration and serving behavior explicitly.

### 6. Apply database migrations

```bash
python manage.py migrate
```

If the project contains model changes without migration files, create the migrations first:

```bash
python manage.py makemigrations
python manage.py migrate
```

### 7. Start the development server

```bash
python manage.py runserver
```

Open the application at:

[http://127.0.0.1:8000/](http://127.0.0.1:8000/)

## Validation Rules

- Profile usernames must contain only letters, numbers, and underscores.
- Usernames must be between 2 and 15 characters long.
- Email addresses are required and must have a valid format.
- Age is optional and cannot be negative.
- Task titles are required and limited to 100 characters.
- Task descriptions and due dates are optional.
